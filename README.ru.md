# Componenta VarExport

Componenta VarExport преобразует поддерживаемые PHP-значения в детерминированные исполняемые PHP-выражения. Библиотека предназначена для генерации файлов конфигурации и DI: она возвращает только выражение, не записывает файлы и не добавляет PHP-тег, `return` или завершающую точку с запятой.

Требуется PHP 8.4 или новее.

## Установка

```bash
composer require componenta/var-export:^2.0@dev
```

## Быстрый старт

```php
use Componenta\VarExport\VarExport;

$exporter = VarExport::withDefaults();

$expression = $exporter->export([
    'debug' => false,
    'ports' => [80, 443],
]);
```

Результат можно сразу встроить в генерируемый PHP-файл:

```php
[
    "debug" => false,
    "ports" => [
        80,
        443,
    ],
]
```

## Публичный API

```php
namespace Componenta\VarExport;

interface VarExportInterface
{
    public function export(mixed $var): ?string;
}

interface VarExportAwareInterface
{
    public function withVarExport(VarExport $varExport): static;
}

final class VarExport
{
    public function __construct(VarExportInterface ...$exporters);
    public static function withDefaults(): self;
    public function export(mixed $var): string;
}
```

`VarExport` вызывает экспортёры в порядке конструктора как для исходного значения, так и для каждого вложенного элемента массива. `null` означает, что экспортёр не поддерживает значение. Любая строка, включая пустую, завершает цепочку. Пользовательский экспортёр отвечает за корректность возвращаемого самостоятельного PHP-выражения.

`withDefaults()` устанавливает публичные экспортёры в таком порядке:

1. `ScalarExporter`
2. `ArrayExporter`
3. `EnumExporter`
4. `ClosureExporter`

## Поддерживаемые значения

- `null`, логические значения, целые числа, числа с плавающей точкой и строки;
- `INF`, `-INF`, `NAN`, ноль со знаком, управляющие символы и бинарные байты строк;
- варианты перечислений в виде полностью квалифицированного `\ClassName::Case`;
- массивы с сохранением порядка, отступом в четыре пробела и завершающей запятой;
- замыкания с доступным исходным кодом и поддерживаемыми захваченными значениями, встроенными в выражение.

Экспортёры по умолчанию не поддерживают произвольные объекты и ресурсы. Если следующий числовой индекс или указатель массива нельзя восстановить литералом, выбрасывается `ExportException`, в том числе для вложенных массивов и захваченных значений. Указатель непустого массива должен находиться на первом элементе; проверка не меняет исходный указатель. Стандартный рекурсивный обход, в том числе при прямом использовании связанного `ArrayExporter`, отклоняет массивы глубже 256 уровней и ссылки в массивах. Для захваченных значений действует отдельный предел в 64 уровня обхода.

Интеграции Config и DI могут добавить свои экспортёры перед стандартными:

```php
use Componenta\VarExport\ArrayExporter;
use Componenta\VarExport\ClosureExporter;
use Componenta\VarExport\EnumExporter;
use Componenta\VarExport\ScalarExporter;
use Componenta\VarExport\VarExport;

$exporter = new VarExport(
    new ConfigValueExporter(),
    new ScalarExporter(),
    new ArrayExporter(),
    new EnumExporter(),
    new ClosureExporter(),
);
```

Составной экспортёр реализует `VarExportInterface` и `VarExportAwareInterface`. Метод `withVarExport()` должен вернуть связанную копию. Оркестратор заменяет исходный экземпляр этой копией, поэтому экземпляр можно безопасно переиспользовать. Метод `withVarExport()` предназначен только для связывания: попытка экспорта до завершения связывания вызывает `ExportException`. Пространство имён `Internal` и методы с пометкой `@internal` не относятся к поддерживаемым контрактам расширения.

`ArrayExporter` и `ClosureExporter` являются составными экспортёрами. Перед прямым использованием их нужно связать:

```php
$arrayExporter = (new ArrayExporter())
    ->withVarExport(VarExport::withDefaults());

$expression = $arrayExporter->export(['answer' => 42]);
```

## Переносимость замыканий

`ClosureExporter` читает исходный код замыкания, сверяет позицию с метаданными Reflection, разрешает переносимые глобальные функции и константы, фиксирует поддерживаемые захваченные значения и строит каноническое выражение.

Автоматические глобальные переменные PHP (`$GLOBALS`, `$_SERVER`, `$_ENV` и остальные суперглобальные переменные) остаются обращениями во время выполнения. Они не считаются захваченными значениями и не фиксируются в сгенерированном выражении.

Восстановленное замыкание сохраняет исходную область видимости именованного класса либо её отсутствие независимо от класса, загружающего выражение. Именованная область видимости должна быть доступна при загрузке как пользовательский класс, интерфейс или трейт; при её отсутствии или несовместимости выбрасывается `ExportException`. Сгенерированное выражение также сохраняет режим `strict_types` исходного файла. При загрузке из файла с противоположным режимом выбрасывается `ExportException`. Сгенерированное выражение изолирует директивы `ticks` от остального файла. Ненулевая внешняя настройка `ticks` исходного файла отклоняется, в том числе при объявлении без блока в предшествующем пространстве имён или функции; сброс настройки до нуля поддерживается.

Экспорт отклоняется для поведения, которое нельзя надёжно воспроизвести в сгенерированном файле:

- захвата по ссылке и ссылок внутри захваченных массивов;
- захваченных значений глубже 64 уровней обхода;
- `$this`, анонимной или несовместимой области видимости класса и локального статического состояния;
- захваченных объектов, ресурсов и замыканий;
- именованных вызываемых объектов;
- `eval`, `include`/`require`, переключения режима PHP, непереносимых внешних директив `declare`, магических констант, вложенных именованных объявлений, неразрешимых неквалифицированных символов с резервным поиском в глобальном пространстве имён, неоднозначных неквалифицированных вызовов функций при наличии и глобальной, и локальной функции, пользовательских констант времени выполнения и функций, существующих только в исходном файле;
- отсутствующего, структурно изменённого, неоднозначного или некорректного исходного кода.

Исходный файл нельзя изменять после создания замыкания. PHP Reflection не предоставляет инструкции тела замыкания, поэтому изменение только тела с сохранением позиции, сигнатуры и захваченных переменных нельзя надёжно обнаружить без выполнения пользовательского кода.

## Граница доверия

VarExport генерирует исполняемый PHP-код и не является песочницей. Экспортируйте только доверенные замыкания и используйте доверенные пользовательские экспортёры. Проверка переносимости сохраняет поведение, но не ограничивает действия восстановленного замыкания при вызове. Захваченные значения могут содержать секреты, которые попадут в сгенерированное выражение. Защищайте сгенерированные файлы от несанкционированного чтения и записи и не выполняйте недоверенный сгенерированный код.

## Ошибки

Все исключения библиотеки реализуют `Componenta\VarExport\Exception\ExceptionInterface`.

- `ExportException` означает, что экспортёр распознал значение, но не смог построить безопасное выражение.
- `UnsupportedValueException` означает, что все экспортёры вернули `null`.

Исключения пользовательских экспортёров не перехватываются.

## Разработка

```bash
composer validate --strict
composer cs-check
composer phpstan
composer test
composer test-coverage
composer mutation
composer benchmark
```

Поддерживаемая тестовая матрица: PHP 8.4 и PHP 8.5.

Бенчмарк выводит медиану времени в микросекундах на операцию по пяти измерениям для скаляров, массивов, перечислений, экспорта замыканий новым и переиспользуемым экспортёром и загрузки сгенерированных замыканий. Для сравнения ревизий используйте одинаковую версию PHP и окружение.
